# 현지화 기여 및 검토 절차

구성원과 관리자가 보는 모든 변경은 한국어와 영어를 함께 제공합니다. 영어를 나중에
번역하는 작업으로 미루거나 내부 식별자를 보이는 대체 문구로 사용하면 안 됩니다.

## 구현 전

1. 실행 중 메시지는 `messages/en.yml`과 `messages/ko.yml`에 짝을 이루는 키를
   추가합니다. 서식 자리표시자는 정확히 같아야 합니다.
2. 새 애플리케이션 명령 설명과 선택지 레이블은 모두
   `CommandTranslator._copy`에 양쪽 언어 메타데이터를 추가합니다.
3. 공개 문서는 항상 언어 쌍을 함께 추가하거나 갱신합니다. 명령 참조, 운영 단계,
   안전 경고도 같은 내용을 유지합니다.

## 자동 검사

프로젝트 의존성이 설치된 환경에서
`python3 -m unittest discover -s tests -v`를 실행합니다.
`test_localization.py`는 카탈로그 키/자리표시자 불일치와 번역되지 않은 명령 설명을
막고, `test_documentation.py`는 문서 쌍, 명령 참조 일치, 마이그레이션 안내 단계를
검사합니다.

## 사람 검토

릴리스 전에는 소유자(또는 명시적으로 기록한 한국어·영어 문구 검토자)가 두 언어의
말투, 용어, 메시지 길이, Discord 표시를 확인합니다. 검토자, 일자, 릴리스 버전,
승인한 예외는 배포 기록에 남깁니다. 이 승인이 없으면 릴리스 점검표를 완료할 수 없습니다.

## 대체 언어 정책

저장된 서버 언어를 먼저 사용합니다. 아직 저장되지 않았다면 Discord 로캘을 사용할 수
있을 때 사용하고, 그렇지 않으면 영어를 안전한 대체 언어로 사용합니다. 카탈로그 키가
없으면 구성원에게 조용히 표시하지 말고 프로그램 오류로 고쳐야 합니다.
