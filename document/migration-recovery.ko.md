# 레거시 공지·릴레이 마이그레이션 복구

이 절차는 기존 `비밀 방` 배포에만 적용됩니다. 새 서버는 레거시 환경 ID나 레거시
스케줄러 cog를 사용하지 않습니다.

## 전환 전

1. PostgreSQL 백업을 만들고, 레거시 스케줄러 cog를 아직 불러오는 배포 버전을 롤백용으로
   보관합니다. 두 버전을 동시에 실행하면 안 됩니다.
2. `SECRET_ROOM_SERVER_ID`, `TOMAK_SUBMISSION_ID`, `TOMAK_NOTIFY_ID`,
   `KYOHOON_SUBMISSION_ID`, `KYOHOON_NOTIFY_ID`, `RELAY_STORY_ID` 값을
   배포 매니페스트에 기록합니다. 이는 배포 시크릿이므로 공개 Discord 메시지나 저장소에
   붙여 넣지 않습니다.
3. 해당 값으로 일반화된 봇을 한 번 시작합니다. 기록은 멱등적으로 가져오고, 이전
   스케줄러 cog는 불러오지 않습니다.
4. 레거시 길드에서 `/admin diagnostics migration`을 실행합니다. 결과가 `일치`여야
   합니다. 다음 예약 주기 전에 채널, 일정, 가져온 릴레이 보상 수 불일치를 해결합니다.

## 검증 기간

정상 토막 일일 주기 한 번과 교훈 주간 주기 한 번 이상을 관찰합니다. 각각 게시 스레드
한 개, 레거시 보상 기록 한 건, 레거시 형식의 기여자 DM, 레거시 형식의 공개 스레드
알림을 확인합니다. 대기열 작업의 멱등 키와 레거시 보상 테이블은 예약 작업 재시도 시
중복 게시·보상을 막습니다.

## 복구

검증에 실패하면 `/admin queue pause`로 해당 대기열을 멈추고 일반화된 봇만 스케줄러로
실행하며 감사/작업 기록을 보존합니다. `/admin queue set-channels` 또는
`/admin queue configure`로 채널·일정을 바로잡고, 게시되지 않은 선택 원본 메시지에만
`/admin queue retry`를 사용합니다. 이미 게시된 메시지의 보상을 수동으로 다시 실행하면
안 됩니다.

코드 롤백이 필요하면 먼저 일반화된 봇을 중지합니다. 일반화된 기록을 제거해야 한다면
데이터베이스 백업을 복원한 뒤, 알려진 레거시 배포만 시작합니다. 두 스케줄러를 동시에
실행하는 것은 안전하지 않습니다.

보상을 받은 릴레이 기여가 삭제되거나 부적격 처리되면 `/admin game reward-reconciliations`에
대기 항목이 생깁니다. 연결된 구성형 보상 원장을 검토한 뒤 기록된 스냅샷으로 돌아가도
괜찮을 때만 `/admin game reward-rollback`을 사용합니다. 이 작업은 해당 플레이어의 이후
진행도도 복원합니다. 레거시 및 공유 월드 정수 보상 변경은 관리자의 문서화된 수동 조정 후
`/admin game resolve-reconciliation`으로 감사 기록을 남겨야 합니다.

## 길드 범위 게임 검증

이관된 게임을 일반 사용에 활성화하기 전에 백업 참조를 보관하고, 레거시 길드의
`guild_game_*` 플레이어·비밀·유기체·알림·릴레이 보상·월드 상태 행을 변경 불가한
`si_*` 원본 및 `game_migration_evidence` 체크섬과 비교합니다. 복구 시에는 새로 만든
길드 범위 행만 제거하거나 백업을 복원할 수 있으며, `si_*` 데이터를 덮어쓰면 안 됩니다.
