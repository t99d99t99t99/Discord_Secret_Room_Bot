# CommunityNoticeBot 시작 안내

CommunityNoticeBot은 구성원이 제출한 글을 정해진 시간에 게시하는 Discord 봇입니다.
공지 대기열, 릴레이 이야기, 선택 기능인 **Essence Foundry**는 서버별로 독립 구성합니다.

기존 `비밀 방` 배포는 전환 기간에 현재 이름과 동작을 유지합니다. 이 이름들은 제품의
기본값이 아니라 기존 서버에서 가져오는 구성입니다.

## 초기 설정

1. Discord 개발자 포털에서 봇 애플리케이션을 만들고 `applications.commands` 범위로 초대합니다.
2. 배포에는 `DISCORD_TOKEN`과 `DATABASE_URL`만 설정합니다. 새 서버에서는 채널·스레드·역할 ID가 필요 없습니다.
3. 봇을 시작한 뒤 대상 서버에서 `/관리 설정 시작`를 실행합니다.
4. 필요에 따라 `/관리 설정 감사채널설정`, `/관리 설정 관리자역할설정`,
   `/관리 설정 운영진설정`를 실행합니다.
5. `/관리 설정 현황`를 확인한 뒤, 필요한 공지 대기열·릴레이 이야기·게임만 구성하거나 활성화합니다.
6. `/관리 대기열 생성`로 첫 기본 대기열을 만든 뒤 해당 대기열에
   `/관리 대기열 신청열기`를 실행합니다. 첫 대기열을 만들면 설정이
   완료되며, 감사 채널과 선택 사항인 게임은 비활성으로 두어도 됩니다.

서버 소유자, **서버 관리** 권한 보유자, 또는 지정한 관리자 역할만 `/관리`을 사용할 수 있습니다.
권한 거부는 호출자에게만 표시됩니다.

## 관리자 명령

설정, 공지 대기열, 릴레이 이야기, 게임, 진단 명령은
[관리자 명령어 참고](../admin_commands.ko.md)를 확인하세요. 답장 기반 검수,
중요한 작업의 확인 버튼, 감사 기록도 해당 문서에서 설명합니다.

## 기본 대기열 만들기

`/관리 대기열 생성`에서 일일 또는 주간 일정을 고르고, 같은 서버의 신청 채널과 게시 채널을 선택합니다.
그다음 `/관리 대기열 신청열기`로 신청 스레드를 열고, `/관리 대기열 보기`로 다음 게시 시각과
적격 신청 수를 확인합니다. 게시 실패나 권한 오류는 `/관리 대기열 재시도`로 복구할 수 있습니다.

명령 전체 목록과 답장 기반 검수 방법은 [관리자 명령어 참고](../admin_commands.ko.md)를 참조하세요.

## 실행 및 개발

설치, 시작 순서, 모듈 역할, 데이터 흐름, 개발 검사는
[코드베이스 안내](codebase.ko.md)를 참고하세요.

## 마이그레이션 안내

저장소의 제품 이름은 **CommunityNoticeBot**입니다. 이 브랜치를 배포할 때 원격 저장소 이름을
바꾸고 가능한 공개 문서 경로에는 리디렉션을 추가합니다. 기존 `비밀 방`, `오늘의 토막상식`,
`이 주의 교훈`, `Secretae Incremental` 표기는 가져온 서버 구성으로 유지됩니다. 전환 전에는
[레거시 마이그레이션 복구 절차](migration-recovery.ko.md)를 따르세요.

## 문제 해결

- `/관리`이 보이지 않으면 봇을 `applications.commands` 범위로 다시 초대하고 Discord 명령
  동기화 시간을 기다립니다. 봇이 해당 채널을 볼 수 있는지도 확인합니다.
- 채널을 선택할 수 없거나 게시가 실패하면 같은 서버의 채널인지, 봇에 채널 보기·메시지 보내기·
  기록 보기·공개 스레드 만들기 권한이 있는지 확인합니다.
- 예약 게시가 중단되면 `/관리 대기열 보기`에서 마지막 결과를 보고 문제를 고친 뒤
  `/관리 대기열 재시도`를 실행합니다. 영속 작업 기록이 재시도 중 중복 게시를 막습니다.
- 보상 분쟁이나 삭제된 기여는 `/관리 게임 보상검토`와
  `/관리 게임 보상조정목록`에서 확인합니다. 스냅샷 복구는 보상 이후의 진행도도
  함께 되돌리며, 공유 월드 변경은 기록된 수동 조정 절차를 따릅니다.

## 업그레이드, 비활성화, 제거

저장소 CLI로 PostgreSQL 백업을 만들고 복원할 수 있습니다. 명령을 실행하는
컴퓨터에 PostgreSQL 클라이언트 도구(`pg_dump`, `pg_restore`)를 설치합니다.
이 도구는 `requirements.txt`에 포함되지 않는 운영체제 패키지입니다. 저장소의
Dockerfile은 컨테이너 실행에 필요한 도구를 설치합니다. 직접 설치할 때는
운영체제 패키지 관리자를 사용합니다. Debian 또는 Ubuntu에서는 다음과 같이
설치할 수 있습니다.

```sh
sudo apt-get install --yes postgresql-common ca-certificates
sudo /usr/share/postgresql-common/pgdg/apt.postgresql.org.sh
sudo apt-get update
sudo apt-get install postgresql-client-18
```

Homebrew를 사용하는 macOS에서는 `libpq`를 설치하고 실행 경로에 추가합니다.

```sh
brew install libpq
export PATH="$(brew --prefix libpq)/bin:$PATH"
```

Railway에서는 저장소 Dockerfile로 배포해 PostgreSQL 18 클라이언트를 설치하세요.
Debian 기본 `postgresql-client` 패키지는 데이터베이스 서버보다 낮은 버전일 수 있습니다.

PostgreSQL 클라이언트는 서버와 같은 주 버전이거나 더 높은 버전을 사용하세요.
기본 백업은 `backups/` 아래 압축 사용자 지정 형식으로 저장됩니다. 이 폴더는
커뮤니티의 비공개 데이터가 포함될 수 있어 Git에서 제외됩니다.

저장소 Dockerfile로 봇을 실행하려면 이미지를 만들고 환경 파일로 배포 비밀값을
전달합니다. `.dockerignore`가 환경 파일을 이미지에 포함하지 않도록 합니다.

```sh
docker build -t secretroombot .
docker run --env-file .env secretroombot
```

```sh
python3 -m database.backup backup
python3 -m database.backup backup --output /secure/path/community.dump
python3 -m database.backup restore /secure/path/community.dump
# 로컬 아카이브는 cron 또는 호스팅 스케줄러에서 실행합니다.
python3 -m database.backup scheduled
```

CLI는 환경 변수 또는 `.env`의 `DATABASE_URL`을 사용하며, `--database-url`로
대상을 지정할 수도 있습니다. 복원은 데이터베이스를 변경하기 전에 확인을
요청합니다. 아카이브에 포함된 객체를 먼저 삭제하려면 `--clean`을 추가하고,
자동화 복원에서만 명시적으로 `--yes`를 사용합니다. 복원 중 데이터 변경을
막도록 봇을 먼저 중지하세요. 백업은 암호화해 애플리케이션 호스트 외부에
보관하고, 별도의 PostgreSQL 데이터베이스에 주기적으로 복원해 확인하세요.

감사 채널로 한 번 업로드하려면 `/백업 업로드`를 사용합니다. 서버 관리자는
`/백업 일정설정`에서 일간 또는 주간 주기, `HH:MM`, IANA 시간대와 주간 일정의
요일(`0` 월요일부터 `6` 일요일)을 지정할 수 있습니다. `/백업 비활성화`는 해당
서버의 일정을 중지합니다. 업로드 일정은 봇에서 실행하고,
`database.backup scheduled`는 호스트 스케줄러에서 별도 로컬 아카이브를 만들 때 사용합니다.

업그레이드 전에는 데이터베이스를 백업합니다. 업데이트 후 봇을 한 번 실행하여 스키마 마이그레이션을 적용하고,
`/관리 진단 마이그레이션` 및 `/관리 설정 현황`를 확인합니다. 대기열·릴레이는 각 수명주기 명령으로
비활성화 또는 보관할 수 있으며 기록은 유지됩니다. `/관리 게임 비활성화`은 게임 진행도를 지우지 않고 새 게임 명령과
보상만 중지합니다. 봇을 제거하기 전에는 활성 기능을 보관/비활성화하고 필요한 감사·구성 기록을 내보낸 뒤
봇 토큰을 폐기합니다. 운영 전환·복구는 [마이그레이션 복구 절차](migration-recovery.ko.md)를 따르세요.

## 언어와 문구 검토

`/관리 설정 언어설정`로 서버 기본 언어를 선택합니다. 저장된 선택이 없으면 Discord 로캘을 사용하고,
확인할 수 없으면 영어로 표시합니다. 한국어와 영어 메시지 카탈로그는 동일 키와 서식을 자동 검증합니다.
릴리스 전에는 소유자가 두 언어의 카탈로그와 관리자·게임 안내를 모두 검토하고 승인해야 합니다.

배포 전에는 [릴리스 점검표](release-checklist.ko.md)를 사용하세요.
